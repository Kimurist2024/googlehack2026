# 本番での確認（2026年11月6日）

公開URL（https://mushitori-hackathon.web.app）で、本物の Code Execution、Gemini（`gemini-3.5-flash-lite`）、Firestore を使って確かめた記録です。データはすべてデモの合成データです。Cloud Run はその日のうちにリビジョン 00006 から 00007（コミット `400c201`）まで更新しており、振り返りの対話と認証は 00006 以前、質問案と生徒ごとの記録は 00007 で確かめました。

## 手順

1. 教員として Google でログインし、デモクラスを作る（提出6人分と、過去2回分の記録）。
2. 問いを作る。6人中4人分ができ、2人は「実行が終わらない」「実行時にエラー」で対象外になる。
3. 受付を開始し、4人が解答する。番号3は、まちがえた問いが指す行の説明を送る。
4. 締め切り、声をかける順、説明を聞きたい行と質問案、これまでの記録を確かめる。

## 結果

| 確かめたこと | 結果 |
|---|---|
| 問いの生成 | 4人分を23秒で作成 |
| 質問案とまとめ | 4人分すべてで Gemini の文が検査を通り（既定の文への差し戻しなし）、締切から10秒でそろった |
| 質問案の中身 | 初めて使い、クラスでも1人だけの `.append()` の行に「6行目で使っているメソッドはどのような働きをしますか。また、なぜこの書き方を選びましたか。」と出た。挙げた行番号はすべて実際のコードと一致 |
| 本人の説明 | Firestore のトランザクションで保存され、教員の画面のその行の下に表示された |
| 生徒ごとの記録 | 過去2回分と今回の3件が残り、教員の「聞いて説明できた」が今回の記録に書き込まれた |
| 振り返りの対話 | 2往復とも Gemini の返答が検査を通り、答えを言わずに行番号でヒントを返した。残り回数は 9 → 8 と Firestore で数えられた |
| 認証 | ログインなし、仮のヘッダー、偽のトークンでの教員の操作はすべて 401 |

## 気づいたこと

- Gemini のまとめに、少し推測の入った言い方が出ることがある（「〜説明できるようになりそうです」）。
- 質問案が、問いの中身をほぼ言い直す形になることがある（「8行目の初期値を0から1に変えると…」）。
- 生徒の説明の欄は、本番では API だけを確かめ、画面は手元で確かめた。
- Firebase Hosting の既定ではブラウザに画面が1時間残ったので、`Cache-Control: no-cache` で配るようにした。
