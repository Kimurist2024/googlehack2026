# ネットが落ちても授業を止めない

> 状態：①〜③は実装済みです（`apps/api/app/offline_api.py`、`apps/api/app/classpack.py`、`apps/api/app/lan_store.py`、`apps/web/offline.js`、`apps/api/scripts/lan.py`）。
> 本番で授業パッケージを作るには、署名の鍵の設定が要ります（[SECURITY.md](../SECURITY.md#デプロイのときに行う設定)）。
> 授業前の準備まで完全にオフラインで行う形（下の「さらに先」）は設計だけです。

## 考え方：準備はクラウド、授業はどこでも

ムシトリでコードの実行と AI が要るのは、**授業前に問いを作る段階だけ**です。授業中に要るのは、配り済みの問い、正解、採点の計算、声をかける順の計算だけで、どれもネットも AI も使いません。

そこで、重い準備は Google Cloud（Code Execution、Gemini、Model Armor）でやり切り、授業はネットがなくても回る形にしました。インターネットの障害で使えなくなるなら表計算ソフトで足りてしまうので、「止まらないこと」自体を価値にします。

あわせて、つながっていること自体を攻撃面として減らします。公式の配布物や更新の経路が乗っ取られる攻撃は実際に起きています（2023年の 3CX のデスクトップアプリ、2024年の xz-utils）。

## 3つの段階

| 状況 | 動き方 | 失うもの |
| --- | --- | --- |
| **① ふだん** | Cloud Run ＋ Firestore で授業。教員は授業前に「授業パッケージを保存」しておく | なし |
| **② ネット障害、LANは動く** | 教員PCで `apps/api/scripts/lan.py` を起動し、パッケージを取り込む。生徒は表示されたアドレスを開き、同じ授業コードと個人コードで入り、解答のあとの自分の言葉の説明も書ける。終わったら結果を書き出し、ネットが戻ったらクラウドに取り込む（説明も一緒に戻る） | 声かけの問いと振り返りのヒントが定型文になる |
| **③ LANも落ちた** | 生徒の端末が解答をためておき、つながったら自動で送る。画面は Service Worker でオフラインでも開ける | その場の採点。持ち時間を過ぎた提出には「オフライン提出」の印が付く |

## 守り方

### 授業パッケージ（①→②）

| 対策 | 内容 |
| --- | --- |
| 署名 | クラウドが ECDSA P-256 で署名し、教員PCは公開鍵で確かめてから使う。本番の秘密鍵は Cloud KMS に置き、アプリの外に出さない。KMS との通信は CRC32C で壊れていないかを確かめる |
| 暗号化 | AES-256-GCM。鍵は保存のたびに作る25文字の解除コードから導く。解除コードはクラウドにも保存せず、画面に1回だけ出す |
| コード | 授業コードと個人コードは scrypt の照合値（クラスごとの塩）でしか入れない。平文もクラウドのハッシュも入らないので、ファイルが漏れても総当たりに年単位かかる |
| 中身を絞る | 1つの課題の授業に要るもの（名簿、問い、正解）だけ |
| 期限 | 課題の保存期間か、発行から7日の早いほう。過ぎたものは教員PCが受け付けない |
| 記録 | 誰がいつ保存したかを監査ログに残す（`package.issued`） |

### 校内LAN版（②）

| 対策 | 内容 |
| --- | --- |
| 外へつながない | クラウドの設定（Firestore、Gemini、Code Execution、Model Armor、署名の鍵）が残っていたら起動しない。試験で、取り込みから書き出しまで外への接続が一度もないことを確かめている |
| 教員の操作は教員PCだけ | LAN に開くのは生徒の入室・解答・振り返り（自分の言葉の説明と定型のヒント）だけ。他は 127.0.0.1 からしか受け付けない。`X-Forwarded-For` は信用しない |
| 問いを作る操作は使えない | コードの実行と AI はクラウドでだけ行う。クラスや課題の作成、提出の受付、問いの生成は 404 |
| 鍵を分ける | 教員PCは自分だけの秘密でトークンを出す。クラウドの鍵は持たず、クラウドのトークンも通らない |
| 保存 | 暗号化したファイル（AES-256-GCM）。鍵は別ファイル、どちらも教員のアカウントだけが読める（0600）。再起動しても授業を続けられる |
| 通信 | 初回起動で証明書を作り、HTTPS で待ち受ける。生徒の端末には学校の管理コンソール（Google 管理コンソールなど）から信頼させる |

### 結果をクラウドに戻す（②→①）

- 教員PCの採点は使わず、**クラウドの正解で採点し直します**。教員PCで正誤を書き換えても結果は変わりません。
- クラウドですでに提出された解答があれば、そちらを正とします。
- 取り込んだ記録には `via: "lan"` の印を付け、監査ログに件数を残します。

### 端末にためた解答（③）

- 解答はその端末にだけ置き、送れたらすぐ消します。問いや結果は Service Worker にも保存しません（共用の端末に生徒のデータを残さない）。
- 入室の期限（2時間）が切れていても、署名が正しく、開始から1日以内なら受け付けます。
- 端末の時計は信用しません。受け付けた時刻はサーバーの時刻で、端末が申告した時刻は印と一緒に記録するだけです。
- 締切のあとに届いた解答にも、授業で聞く一問を作ります。

## 使い方

```sh
cd apps/api
# ネットがあるうちに1回だけ：クラウドの公開鍵を教員PCに保存する
.venv/bin/python scripts/lan.py --fetch-key https://mushitori-hackathon.web.app

# 授業でネットが落ちたら：LAN だけで起動する
.venv/bin/python scripts/lan.py
```

起動すると、生徒が開くアドレスと証明書の指紋が表示されます。教員はその PC で `https://127.0.0.1:8443` を開き、保存しておいた授業パッケージと解除コードを入れます。

## さらに先（設計のみ）

授業前の準備までネットなしで行うには、次の2つが要ります。今は扱いません。

- **コードの隔離実行：** 教員PCで生徒のコードを動かすには、Code Execution の代わりの隔離が要ります。WebAssembly（CPython の WASI 版を wasmtime で動かす）を第一候補にします。今の実行ラッパーの多層防御は、その内側にそのまま重ねます。
- **AI：** 教員PCで Gemma を動かせば、問いの選定と説明もオフラインでできます。出力の機械的な検査は今と同じく必須にします。

配布物そのものを信じられるように、依存パッケージのハッシュ固定と、配布物の署名もあわせて必要です。
