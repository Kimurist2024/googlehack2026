# 画面（apps/web）

教員と生徒が使う画面です。ビルド不要の HTML・CSS・JavaScript で、本番は Firebase Hosting から配信します（リポジトリ直下の `firebase.json`）。手元では [`apps/api/scripts/dev.sh`](../api/scripts/dev.sh) が同じファイルを配ります。

## 画面

| 画面 | できること |
|---|---|
| 教員 | Google でログインし、デモクラスを作る、問いを作る、受付を開始・締切する。締切のあとは、声をかける順、本人の説明を聞きたい行と根拠、質問案、これまでの記録を見て、「聞いて説明できた」「説明が難しかった」などを記録する |
| 生徒 | 授業コードと個人コードで入室し、自分のコードについての問いに答える。解答のあと、まちがえた問いが指す行を自分の言葉で説明して送り、答えを言わない振り返りの対話を使う |

## ファイル

| ファイル | 内容 |
|---|---|
| [`index.html`](./index.html) | 教員と生徒の画面の骨組み |
| [`app.js`](./app.js) | API の呼び出しと画面の組み立て。教員のログインは Firebase Hosting の `/__/firebase/init.json` を読んで Firebase Auth を使う。読めなければ手元の開発として動く |
| [`style.css`](./style.css) | 見た目。明るい表示と暗い表示の両方に対応 |
| [`offline.js`](./offline.js) | 通信が切れたときに解答を端末にためて後で送る。授業パッケージの保存と、校内LAN版の画面 |
| [`sw.js`](./sw.js) | Service Worker。画面の部品だけを置き、ネットが切れても画面を開けるようにする。問いや結果は置かない |

## 決めごと

- 生徒のコードと文章は、すべて `textContent` で入れます。HTML としては解釈させません。本番の画面は CSP と Trusted Types（`require-trusted-types-for 'script'`）で、`innerHTML` などへの文字列の代入そのものをブラウザが拒否します。
- コードの表示では合字を切ります（`font-variant-ligatures: none`）。`>=` が1文字に見えると、問いの読み違いにつながるためです。
- AI が書いた文には「質問案とまとめはAI」「AI」などの印を付け、既定の文（テンプレート）と見分けられるようにします。
- 説明を聞きたい行には「AIを使ったかどうかの判定ではありません」と添えます。

## RSIテスト

サーバーを `sh apps/api/scripts/dev.sh --rsi-test` で起動したときだけ、画面上部に「RSIテスト」のタブが出ます（手元の開発のときだけ。本番の Firebase Hosting は記録を配りません）。ここから、合成データによる実測記録をログインなしで再生できます。「テストを再生」「一時停止」「次のステップ」「最初に戻す」で進行を操作し、候補を選ぶと点数、採否、親からの指示文の差分、失敗と実行記録の抜粋を確認できます。最後に別データでの比較と推薦を表示します。

これは保存済み記録の再生で、新しいAI呼び出しやコード実行、本番への反映は行いません。実行中のRSIを監視する機能ではありません。現在の再生元は `20261107-000819-probe_planner` で、その c006 を probe_planner の v003 として採用しました。公開用の記録は、リポジトリ直下で `python apps/api/scripts/export_rsi_demo.py [記録のID]` を実行して生成します（省略するとこの記録）。実在の生徒のデータを公開用記録に使わないでください。
